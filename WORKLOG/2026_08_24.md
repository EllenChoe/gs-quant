### 에이전트 프롬프트 개선 핵심

- `analyst_technical`: "계산해라" → "이미 계산된 숫자를 해석해라"로 역할 전환
- `trader`: R:R 1:2 미만 BUY 금지, composite_score와 모순 시 자동 HOLD
- `fund_manager`: 자동 HOLD 규칙 (confidence<0.5, 리스크팀 2/3 반대 시)
- 전체: "숫자 근거 없는 판단 금지" 규칙 강제

### gs_quant 참조 부분

| gs_quant 모듈 | 참조 내용 | 적용 위치 |
|---------------|-----------|-----------|
| `timeseries/technicals.py` | SMA, EMA, Bollinger Bands, RSI, MACD 구현 패턴 | `engine/indicators.py` |
| `timeseries/econometrics.py` | Sharpe Ratio, Max Drawdown, Volatility 연환산(√252) | `engine/indicators.py` risk_metrics |
| `timeseries/statistics.py` | Window 기반 롤링 계산 패턴, pd.Series 입출력 통일 | 모든 지표 함수 시그니처 |
| `timeseries/algebra.py` | Interpolate 정렬 전략 (intersect, nan, step) | 시계열 정렬 로직 |
| `backtests/` 아키텍처 | 선언적 전략 정의 + 엔진이 실행 최적화 패턴 | 에이전트 파이프라인 구조 |
| `risk/measures.py` | RiskMeasure 타입 계층 (Score/Signal 구조) | composite_signal 설계 |

**핵심 설계 차용:**
- gs_quant는 `@plot_function` 데코레이터로 함수를 Marquee에 자동 노출 → 우리는 `compute_all_indicators()` 하나로 모든 지표를 일괄 계산하여 에이전트에 주입
- gs_quant의 "LLM은 계산하지 않는다" 철학 (MCP 서버가 데이터를 제공하고 LLM은 해석만) → 동일 패턴 적용

### 전략 v3 핵심 변경

**매수 필터 추가:**
- RSI > 75 → 절대 매수 금지
- Bollinger %B > 0.9 → 매수 금지
- ADX > 25 && -DI > +DI → 하락 추세 매수 금지
- 시가 대비 +15% 초과 → 추격매수 금지
- 스크리너 등락률 +10% 상한 (기존 +25%)

**매도 개선:**
- 고정 -6% 손절 → ATR×2 동적 손절 (범위: -2%~-5%)
- 고정 -4% 트레일링 → ATR×1.5 동적 트레일링 (최소 -2.5%)

**스크리너 강화:**
- 가격 하한: 1,000 → 2,000원
- 가격 상한: 100,000 → 50,000원
- 거래대금: 10억 → 20억+

### gs_quant 참조 부분

| gs_quant 모듈 | 참조 내용 | 적용 위치 |
|---------------|-----------|-----------|
| `timeseries/technicals.py` | RSI Wilder's smoothing (ewm alpha=1/period) | `core/indicators.py` rsi() |
| `timeseries/technicals.py` | MACD (EMA12-EMA26, Signal EMA9) | `core/indicators.py` macd() |
| `timeseries/technicals.py` | Bollinger Bands (%B, bandwidth) | `core/indicators.py` bollinger_bands() |
| `timeseries/statistics.py` | ADX (+DI/-DI 방향성 지표) | `core/indicators.py` adx() |
| `timeseries/econometrics.py` | Volatility 연환산 (√252), Sharpe Ratio | `core/indicators.py` volatility_ann() |
| `risk/core.py` | RiskKey 기반 결과 라우팅 패턴 | composite_signal score 시스템 |
| `backtests/triggers.py` | Trigger 조건 체계 (Mkt, Risk, Date) | should_buy()의 다중 필터 체계 |
| `backtests/actions.py` | ATR 기반 포지션 관리 | calculate_dynamic_stop_loss() |
| `markets/core.py` | Context Manager 배치 패턴 | compute_signal_score() 일괄 계산 |

**핵심 설계 차용:**
- gs_quant의 `RiskMeasure` 시스템처럼, 여러 지표를 하나의 `compute_signal_score()`로 통합 → 단일 score(-100~+100)로 판단
- gs_quant의 `BacktestEngine`이 CalcType(simple/path_dependent)으로 실행 최적화하듯, should_buy()가 필수 조건을 먼저 체크하고 비용이 큰 계산은 나중에
- gs_quant의 ATR 사용 패턴 (변동성 정규화) → 동적 손절/트레일링에 직접 적용

## 3. 실전 데이터 분석 (KIS_BOT_RESULTS)

**입력:** trades.csv (4,381건), trade_details.jsonl (4,381건), KIS_TICK_DATA (34일×50종목, 425MB)

### 핵심 발견

- 무한루프 버그: 7/15에 2,143회 반복매수 (race condition)
- 대형 손절(-6% 이하) 81건이 전체 손실의 핵심 (-498%)
- 평균 시가 대비 +6.9% 추격매수 후 진입 → 거짓 돌파
- ATR/가격 비율 평균 9.1%인데 고정 -6% 손절은 너무 좁음

### 틱 기반 백테스트 결과

| 항목 | v2 (기존) | v3 (개선) |
|------|-----------|-----------|
| 누적 손익 | -43.3% | -11.7% |
| 승률 | 31.2% | 28.8% |
| PF | 0.61 | 0.83 |
| 최대 단일 손실 | -6.0% | -2.5% |
| 평균 손실 | -2.59% | -1.46% |

→ 손실 73% 축소. PF 0.83이면 파라미터 미세 튜닝으로 수익 전환 가능하나,
  34일 11종목 데이터로는 과적합 위험이 있어 보수적 파라미터로 실전 투입 후 데이터 축적 권장.
